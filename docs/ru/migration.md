# Миграция и восстановление

[English](../en/migration.md) | [Установка](guide.md)

## Переименование после 0.2.0-rc.2

Перед заменой файлов остановите старые сервер и оболочку. Сохраните прежний пакет целиком и приватную копию данных/конфигурации. Старую и новую версии нельзя запускать одновременно.

| Прежнее имя                                  | Новое имя                                |
| -------------------------------------------- | ---------------------------------------- |
| `ATBL-SE`, репозиторий `nd4y/atbl-se`        | `atblse`, репозиторий `nd4y/atblse`      |
| `autoblow.local/emulator`                    | `github.com/nd4y/atblse`                 |
| `AutoblowLocal.exe`                          | `atblse.exe`                             |
| `autoblow-server`, `autoblow-catalog-import` | `atblse-server`, `atblse-catalog-import` |
| `vacuglide-simulator`                        | `atblse-simulator`                       |
| `cmd/autoblow-windows`                       | `cmd/atblse-windows`                     |
| Переменные `AUTOBLOW_*`                      | `ATBLSE_*`                               |
| `%LOCALAPPDATA%/AutoblowLocal`               | `%LOCALAPPDATA%/atblse`                  |

Остальные каталоги команд соответствуют новым именам файлов. Обновите ярлыки, сборочные команды и переменные Compose. Существующие данные и конфигурация NAS остаются в явно выбранных каталогах: переименование не должно создавать пустые тома взамен прежних. JSON-конфигурация и версия записи сценария совместимы. Официальные `/autoblow/*`, `/vacuglide/*`, заголовки/домены устройства и имена SDK относятся к протоколу.

## Данные Windows

При первом запуске оболочка захватывает блокировки старого и нового имени. Миграция запрещена, пока занят прежний порт API. Данные копируются во временный соседний каталог, файлы сбрасываются на диск и проверяются SHA-256. Только полная копия публикуется переименованием каталога. Исходный каталог остаётся резервной копией. Пределы: 4096 записей и 1 GiB; ссылки и junction запрещены. Маркер миграции содержит версию 1 и хеши без содержимого файлов. Готовый новый каталог используется повторно; два каталога без маркера вызывают ошибку вместо скрытого слияния. Незавершённая копия остаётся неактивной; повторная попытка создаёт другой временный каталог.

Прежние имя Wi-Fi и пароль сохраняются, включая старый SSID. Только чистая установка получает имя `atblse`. Настройка брандмауэра проверяет файл и интерфейс перед заменой трёх собственных правил и их прежних имён; требуется обычное явное повышение прав. Чужие правила не удаляются.

Для отката остановите новое приложение и восстановите полную копию до миграции вместе со старым пакетом. Не объединяйте активные каталоги и не считайте, что старая копия содержит последующие изменения новой версии. Работа Hotspot и обновление установленного пакета требуют отдельной физической приёмки; изолированные тесты миграции её не заменяют.

## Состояние, отзыв ключа и резервная копия

Видимыми становятся только целые файлы после сброса данных на диск. В Linux также сбрасывается родительский каталог; Windows использует write-through rename. Повреждённый ключ или привязка останавливают запуск с указанием восстановления. После сбоя могут остаться `.pending-*`: они не загружаются и учитываются в квоте. Остановив всех писателей, перенесите их в приватную резервную копию перед повтором. Зависшую `.import-lock` каталога допустимо удалить только после проверки, что импорт не выполняется.

Копируйте каталоги данных и конфигурации целиком при остановленном сервере. Для проверки восстановления используйте приватный временный каталог, loopback и виртуальный клиент; реальное устройство к этой копии не направляйте. Проверьте ключ, привязку и контрольные суммы сценариев до замены рабочих данных. Удаление экспортов требует явного решения владельца.

Для отзыва локального ключа остановите сервер, сохраните копию, удалите только `control-token`, запустите сервер и обновите ключ во всех клиентах. Старые потоки событий тоже закроются. Повреждённый `paired-device` восстановите из копии либо удалите при остановленном сервере и выполните привязку заново. Файлы сценариев сохраняются. Токен устройства и его потоки событий действуют только в пределах текущего подключения; независимый локальный ключ позволяет читать статус офлайн.

Одновременно принимаются две загрузки сценариев; следующие получают HTTP 429. Чтение тела запроса ограничено 15 секундами. Отмена освобождает место, STOP не занимает квоту загрузки. Для событий предел составляет 32 подписчика и 16 событий в очереди каждого. Это ограничения приёма, а не доказательство производительности или физической безопасности.

Обычные обработчики API и загрузки бинарных файлов имеют общую квоту 32 параллельных запроса. Перегрузка возвращает HTTP 429 и `Retry-After: 1`; STOP и завершение сервера обходят эту квоту, но требуют авторизацию. У SSE и WebSocket устройства отдельные лимиты. Доступность при атаке на сетевые соединения не гарантируется.
