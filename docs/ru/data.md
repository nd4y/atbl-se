# Данные, файлы каталога и восстановление

[English](../en/data.md) | [Конфигурация](configuration.md)

## Закрытое состояние

| Путь внутри `dataDir` | Содержимое                                                                       |
| --------------------- | -------------------------------------------------------------------------------- |
| `control-token`       | Локальный ключ управления; владение им даёт доступ к управлению                  |
| `paired-device`       | MAC явно привязанного устройства                                                 |
| `sync-scripts/`       | Преобразованные синхросценарии с хешами целостности                              |
| `local-catalog/`      | Импортированные штатные бинарные сценарии по UUID каталога, с хешами целостности |

В Windows состояние сервера находится в `%LOCALAPPDATA%/atblse/server`, а настройки запуска и пароль точки доступа - в `%LOCALAPPDATA%/atblse`. Весь каталог должен оставаться закрытым. Конфигурация отдельного сервера и собственные TLS-файлы могут находиться вне `dataDir`; учитывайте их при резервировании.

Запись состояния использует временный файл, сброс данных и атомарную публикацию. Незавершённые файлы учитываются в лимитах хранилища; не удаляйте их при работающем сервисе. Устойчивость к аварии/потере питания на целевой файловой системе требует отдельной приёмки. Сервер не хранит аккаунт производителя или видеотеку. Содержимое штатных слотов находится на устройстве и не входит в копию серверного состояния.

## Импорт штатного файла каталога

Нужны бинарный файл, который вы вправе использовать, и соответствующий UUID каталога. Соберите импортёр из тех же исходников, что и сервер:

```sh
go build -o out/atblse-catalog-import ./cmd/atblse-catalog-import
./out/atblse-catalog-import --data-dir data --uuid <catalog-uuid> --file <script.bin>
```

Значения в угловых скобках - заполнители. В Windows используйте имя с `.exe`. Импортёр проверяет штатный формат и сохраняет файл локально; команд устройству он не отправляет. Он не скачивает каталог и не придумывает UUID. Для замены слота авторизованный внешний клиент затем вызывает `/vacuglide/local-script/replace` с `replacedLocalScriptIndex` и `newLocalScriptUuid`, при выполненной привязке и включённых флагах. Метаданные идентификаторов исходного каталога включены в проект; бинарная библиотека производителя - нет.

Для автономного анализа выберите выходные пути, которых ещё нет:

```sh
python research/vacuglide_binary.py decode input.bin output.json --csv analysis.csv
```

Декодер сохраняет штатные события, включая клапаны. Позиционный Funscript не заменяет бинарный файл без потерь. См. [формат API](api.md) и модель тактов в [разработке](development.md). Наличие файла не даёт права на его распространение; не добавляйте закрытые захваты или контент производителя в Git.

## Резервирование и восстановление

1. Остановите воспроизведение и убедитесь, что процесс сервера завершился. В Windows используйте остановку в приложении перед его закрытием.
2. Скопируйте закрытый каталог данных, конфигурацию и собственные TLS-ключ/сертификат в защищённое хранилище. Сохраните ограниченные права и запишите версию сервера.
3. Сначала восстановите копию в отдельный каталог. Запустите её только на loopback, без настоящего устройства и перенаправления сети. Проверьте чтение конфигурации, health, авторизацию ключом и целостность сохранённых файлов.
4. Остановите проверочный экземпляр. Укажите восстановленные каталоги в рабочей конфигурации и проверьте права фактической учётной записи сервиса.

Не запускайте два сервера с одним каталогом состояния. Сохраняйте исходную копию до проверки восстановленного экземпляра. Восстановление копирует ключ управления: обладатель резервной копии получает и ключ. Восстановление на целевой файловой системе и переподключение устройства требуют отдельной приёмки.

## Отзыв или восстановление локального ключа

Остановите сервер. Восстановите исправный `control-token` из закрытой копии либо удалите только этот файл, чтобы отозвать ключ и создать новый при следующем запуске. Обновите сохранённые ключи клиентов. Для решения проблемы ключа не удаляйте привязку и каталоги сценариев. Некорректный файл ключа останавливает запуск, а не заменяется молча. После смены проверьте отказ со старым ключом и работу нового; значения ключей не прикладывайте к отчёту об ошибке.
