# Установка и локальная сеть

[English](../en/guide.md) | [README](../../README.ru.md)

Для настольной установки используйте [оболочку Windows](windows.md). Ниже описаны отдельный сервер и NAS. Подготовьте файлы, образы и конфигурацию до отключения интернета. Управление устройством использует локальную сеть; загрузка сценария по внешнему URL требует доступности его источника.

## Отдельный сервер

Выполните из корня репозитория:

```sh
go build -o out/atblse-server ./cmd/atblse-server
./out/atblse-server --version
```

Создайте приватный `server.json`. Этот пример слушает только loopback и подходит для локальной разработки клиентов:

```json
{
  "deviceListen": "127.0.0.1:20443",
  "apiListen": "127.0.0.1:20880",
  "dataDir": "data",
  "maxSpeed": 15
}
```

```sh
./out/atblse-server --config server.json
```

Откройте `http://127.0.0.1:20880/` и введите ключ из `data/control-token`. `GET /health` сообщает версию `0.2.0-rc.3`, но не подтверждает подключение устройства. Команда `--healthcheck --config server.json` проверяет этот адрес и возвращает ненулевой код при ошибке. Ctrl+C или SIGTERM завершает сервер с попыткой STOP перед закрытием соединения устройства.

Для физического устройства привяжите `deviceListen` к подходящему LAN-адресу и направьте TCP 443 устройства на этот listener. Настройте DNS по вариантам ниже. Оставляйте API на loopback, если удалённый клиент не требуется. Все [параметры конфигурации](configuration.md) заданы явно; относительный путь данных считается от рабочего каталога процесса.

## Docker на NAS

Dockerfile ожидает готовый Linux-файл и набор доверенных CA. На Linux-машине сборки, из корня репозитория:

```sh
mkdir -p out/image
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o out/image/atblse-server ./cmd/atblse-server
cp /etc/ssl/certs/ca-certificates.crt out/image/ca-certificates.crt
docker build -f deploy/Dockerfile -t atblse:0.2.0-rc.3 out/image
docker save -o out/atblse-image.tar atblse:0.2.0-rc.3
```

Пример рассчитан на amd64. Для NAS нужна соответствующая архитектура; другие архитектуры требуют отдельной приёмки. Перенесите архив образа, `deploy/compose.yaml` и `deploy/server.example.json` на NAS. Загрузите образ командой `docker load -i atblse-image.tar`.

Подготовьте два приватных абсолютных каталога: данные и конфигурация. Поместите `server.example.json` во второй каталог под именем `server.json`. Задайте их пути через `ATBLSE_DATA_DIR` и `ATBLSE_CONFIG_DIR`. UID/GID 65532 контейнера нужны запись в данные и чтение конфигурации. Запуск выполняется явно:

```sh
docker compose -f deploy/compose.yaml up -d emulator
```

Compose использует `pull_policy: never`, `restart: no`, файловую систему корня только для чтения, отсутствие дополнительных capabilities, 96 MiB RAM и 0.5 CPU. TLS-порт хоста 20445 соответствует 20443 контейнера, API 20881 - 20880. В примере DNS выключен, Compose не публикует порт DNS. Публикация репозитория или загрузка образа не запускает сервис.

## Варианты DNS и роутера

Устройство подключается к `latency.autoblowapi.com` и региональным узлам в `autoblowapi.com`. Направляйте на локальный сервер только нужное устройство. DNS меняет адрес, но не порт.

1. **Отдельный DNS через DHCP.** В OpenWrt/dnsmasq назначьте устройству DHCP tag и option 6 с выделенным локальным резолвером. Имена `autoblowapi.com` должны разрешаться в локальный адрес сервера, доступный устройству как TCP 443.
2. **Переопределения резолвера.** Используйте DNS роутера, Pi-hole или AdGuard для `latency.autoblowapi.com` и выбранного регионального узла либо поддерживаемую wildcard-зону. Общие изменения действуют и на других клиентов. Публичная AAAA-запись не должна конкурировать с локальным маршрутом.
3. **NAS с занятым портом 443.** Возвращайте устройству LAN-адрес роутера и выполняйте DNAT только его TCP 443 на TLS-порт NAS 20445. При необходимости добавьте соответствующий hairpin SNAT. Если перехватывается DNS, направляйте только UDP/TCP 53 этого устройства на локальный резолвер. Прямой обмен узлов в одной подсети не проходит через DNAT роутера.

Это схемы настройки OpenWrt/dnsmasq и MikroTik, а не скрипт автоматического изменения роутера. Сохраните независимый доступ к его управлению. Проверьте совпадения правил и счётчики, затем подключение и привязку в панели. Если путь не работает, восстановите только изменённые записи DHCP/DNS/NAT. Не публикуйте API и порт устройства в интернете. Приёмка сети, перезапуска и потери WAN на реальном устройстве остаётся открытой.
