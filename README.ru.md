# ATBL-SE

**Autoblow Server Emulator**

[English](README.md)

![Изолированный локальный сервер и виртуальный VacuGlide](docs/assets/preview.svg)

Локальный сервер для VacuGlide 2 со штатной прошивкой, панелью диагностики и API для приложений, включая VacuGlide Studio.

- Готовый сервер запускается и работает без интернета и облачного аккаунта.
- Переносимое ядро на Go, отдельная Windows-оболочка с точкой доступа и Docker-конфигурация NAS с отключённым автоматическим перезапуском.
- Ручная скорость и клапаны, 30 локальных слотов, преобразование Funscript/CSV, передача сценариев, позиционирование, повтор и события.
- Отдельный виртуальный клиент и стенд на loopback для разработки без устройства.

**Кандидат 0.2.0-rc.2.** Профиль прошивки - VacuGlide 2 `1.03`/`1.0.3`. Программные проверки отделены от физической приёмки. Кандидату ещё нужна проверка реального устройства, Windows Hotspot, потери сети и питания. AI Ultra, облачные аккаунты, видеосервисы и обновление прошивки не входят в проект.

## Попробовать локальный стенд

Нужен Go 1.24 или новее; проверки выполняются на Go 1.27.3:

```sh
go build -o out/vacuglide-simulator ./cmd/vacuglide-simulator
./out/vacuglide-simulator --lab --duration 10m
```

В Windows соберите с `-o out/vacuglide-simulator.exe` и запустите этот файл. Команда выводит временный адрес панели, локальный ключ и синтетический MAC. Откройте адрес, введите ключ и подтвердите сопряжение виртуального устройства. Обращений к официальному сервису нет. При штатном завершении временные данные стенда удаляются.

Для автономной сборки заранее получите зависимости разработки. Готовое приложение при запуске их не скачивает. Панель и Windows-оболочка сейчас используют русский интерфейс.

## Использовать сервер

Соберите `./cmd/autoblow-server`, подготовьте приватную конфигурацию по `deploy/server.example.json` и следуйте [инструкции установки и API](docs/ru/guide.md). API должен оставаться приватным. Скорость по умолчанию ограничена 15%; сценарии и управление внешними клиентами включаются явно.

Сеанс панели требует продления. Во внешнем API остановкой управляет клиент. После потери связи сервер не может подтвердить физическую остановку мотора; автоматического возобновления нет.
